# Спецификация проекта: Генератор шаблонов заявок (Transactioner)

## Описание
Простое кроссплатформенное приложение для создания шаблонов заявок на депозиты и выводы в покер-румах. Предназначено для стандартизации процесса и снижения количества ошибок из-за невнимательности при ручном заполнении данных сотрудниками.

## Журнал прогресса
- **[ГОТОВО]** Сбор требований и формирование архитектуры.
- **[ГОТОВО]** Выбор технологического стека (Electron + React + Tailwind + SQLite).
- **[ГОТОВО]** Настройка окружения: Vite + Electron + TailwindCSS v4 + better-sqlite3 (пересборка под Electron 32).
- **[ГОТОВО]** Схема БД: таблицы `players` (основной контакт, default_wallet, default_wallet_network, last_used_at), `player_contacts` (несколько мессенджеров/контактов игрока) и `accounts` (room_name, room_username, room_player_id, email). IPC-хендлеры `search-player`, `save-player`, `get-all-players`, `get-player-by-id`, `delete-player`, `update-default-wallet-details`.
- **[ГОТОВО]** UI — Экран поиска игрока (`SearchPlayerView.tsx`) с поиском по части юзернейма/номера/любого контакта и списком совпадений при нескольких результатах.
- **[ГОТОВО]** UI — Экран добавления игрока (`AddPlayerView.tsx`) с несколькими контактами/мессенджерами, кошельком по умолчанию и аккаунтами в румах.
- **[ГОТОВО]** UI — Экран формы заявки (`FormView.tsx`): выбор рума, тип операции (Депозит/Вывод), динамические поля, автоподстановка контакта из профиля игрока, генерация шаблона, копирование.
- **[ГОТОВО]** Генерация шаблонов для всех трёх румов (RedStar, Champion Poker, Nexa) в обоих направлениях.
- **[ГОТОВО]** UI — Список игроков (`PlayerListView.tsx`) с открытием игрока и переходом к редактированию.
- **[ГОТОВО]** UI — Экран редактирования существующего игрока (`EditPlayerView.tsx`) с изменением списка контактов, аккаунтов, кошелька по умолчанию и удалением игрока.
- **[ГОТОВО]** Защита от повторного добавления контакта с тем же каналом связи и username/номером: создание дубля блокируется, редактирование обновляет только выбранного игрока по `id`.
- **[ГОТОВО]** Кошелек и сеть/монета по умолчанию для выводов: значения хранятся в профиле игрока, автоматически подставляются в форме вывода и могут быть заменены после подтверждения при вводе новых данных.
- **[ГОТОВО]** Мягкая валидация обязательных полей перед копированием: незаполненные поля подсвечиваются и показываются в предупреждении, при этом копирование шаблона не блокируется.
- **[ОЖИДАЕТ]** Сборка финального дистрибутива (.dmg / .exe).

## Пользовательский путь (User Flow)
1. Сотрудник вводит/вставляет **юзернейм игрока из мессенджера** или часть любого сохраненного контакта/номера.
2. Приложение делает поиск по локальной базе данных и отображает **список покер-румов**, в которых у данного игрока зарегистрированы аккаунты.
3. Сотрудник выбирает нужный рум из предложенного списка.
4. Выбирается тип операции: **Депозит** или **Вывод**.
5. В зависимости от выбора открывается **форма для заполнения**. Известные данные (например, юзернейм в руме, Player ID, контакт, кошелек и сеть/монета по умолчанию для вывода) подтягиваются из базы автоматически.
6. Система генерирует **готовый шаблон заявки** в текстовом формате и предоставляет кнопку **Скопировать**.
7. Если при выводе сотрудник вводит кошелек или сеть/монету, отличающиеся от сохраненных в профиле игрока, приложение предлагает заменить значения по умолчанию.

## Технические детали и требования
*(В процессе уточнения с заказчиком)*
* **Платформа:** Кроссплатформенное десктопное приложение.
* **Каналы общения с игроками:** Telegram, WhatsApp, Discord, Teams, Email.
* **Стек:** Electron, React, TypeScript, TailwindCSS, Vite, **SQLite (локальная БД)**
* **База данных:** Хранение связок "Игрок -> несколько контактов/мессенджеров -> доступные аккаунты в покер-румах", а также кошелька и сети/монеты по умолчанию для выводов. Ожидаемый объем: до нескольких сотен игроков.
* **Уникальность контактов:** Повторное добавление той же пары "канал связи + юзернейм/номер" запрещено, чтобы новые данные не перезаписывали существующую карточку.
* **Список покер-румов:** Nexa, Champion Poker, RedStar

## Поля и Форматы шаблонов
Анализ предоставленных примеров показал следующие необходимые поля для каждого рума:

**1. RedStar**
*   **Депозит:** Юзернейм, Сумма, TX ID (хеш транзакции).
*   **Вывод:** Юзернейм, Сумма, Сеть/Монета (например, USDT TRC20), Адрес кошелька.
*(Особенность: нет тега ответственного сотрудника и контактов игрока)*

**2. Champion Poker**
*   **Депозит:** Юзернейм, Email, Сумма (может включать конвертацию), TX Link (ссылка на транзакцию), Контакт игрока (TG/WA + значение).
*   **Вывод:** Юзернейм, Email, Сумма, Сеть/Монета, Адрес кошелька, Контакт игрока.
*(Особенность: используется тег `@TanyaAkaieva` в начале)*

**3. Nexa**
*   **Депозит:** Player ID, Юзернейм, Email, Сумма, TX Link, Контакт игрока.
*   **Вывод:** Юзернейм, Player ID, Сумма, Сеть/Монета, Адрес кошелька, Контакт игрока.
*(Особенность: используется тег `@TanyaAkaieva` в начале, требуется Player ID)*
