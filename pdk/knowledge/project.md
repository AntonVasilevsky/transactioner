# transactioner

## Idea

Transactioner — кроссплатформенное десктопное приложение для сотрудников, которые обслуживают игроков покер-румов. Оно хранит локальные карточки игроков и справочник румов, помогает проверять данные и транзакции и формирует готовые к копированию шаблоны для депозитов, выводов, рейкбека и проверки привязки, чтобы сократить ручные ошибки.

Текущая локальная версия считается доведённой до пользовательского результата, когда сотрудник может найти или создать игрока, выбрать его аккаунт и рабочий сценарий, получить корректный текст или TSV, безопасно скопировать результат, а данные и резервные копии сохраняются между обновлениями; распространяемые сборки должны работать на macOS и Windows.

Развитие продукта разделено на два этапа: текущая версия остаётся локальным десктопным приложением, а будущая общая многопользовательская версия является отдельным последующим этапом. Неопределённые интеграции будущей общей версии не входят в требования текущей локальной версии.

## Constraints

- Текущая реализация — Electron + React + TypeScript + Tailwind CSS + Vite; локальные прикладные данные хранятся в SQLite через `better-sqlite3`.
- Приложение должно оставаться кроссплатформенным для macOS и Windows и простым для ежедневной операторской работы.
- Текущая локальная SQLite-БД и её резервные копии должны переживать обновление приложения; перед изменением справочника румов создаётся snapshot, также используется ежедневный backup.
- Секретные API-ключи не хранятся в Git. Нельзя коммитить `docs/supabase/creds.txt` и содержимое `build/private/`.
- Release workflow из `AGENTS.md` обязателен: при distributable build + push версия повышается ровно один раз, версии lock-файлов сверяются, release notes дополняются до сборки, затем проходят полные тесты и production build; для in-app update нужен GitHub Release с соответствующим тегом и installers.
- Нельзя без подтверждённого сценария придумывать бизнес-правила, поля румов, страны, сделки или финансовые данные; существующие требования и код при расхождении фиксируются как gap.
- Out of scope текущей локальной версии: прямая интеграция с Google Docs/Sheets или Notion, встроенный ИИ, серверная аутентификация и полноценная офлайн-синхронизация с разрешением конфликтов.
- Out of scope MVP проверки привязки: Google API, история проверок в приложении и автоматическая обработка ответа; текущий поток формирует запрос и TSV для буфера обмена.
