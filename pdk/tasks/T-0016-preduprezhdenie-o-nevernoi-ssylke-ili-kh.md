## Goal

Запрос владельца (2026-10-03): после ложной тревоги «приложение перестало искать транзакции» — в поле депозита была вставлена ссылка на адрес кошелька (`etherscan.io/address/…`), поиск не запускался и поле молчало. Поле «TX ID / Ссылка на транзакцию» должно объяснять, почему поиск не идёт: адрес вместо транзакции, неполный хеш (мало символов), случайный текст. Если длина хеша правильная (64 символа), поиск идёт как раньше, а при неудаче уже показывается «Транзакция не найдена».

## Acceptance

- Ссылка на адрес или сам адрес (EVM, TRON, BTC) → «Это адрес кошелька, а не транзакция…».
- Неполный хеш → «Хеш транзакции неполный: N из 64 символов…».
- Случайный текст или короткие цифры → «Не похоже на ссылку или хеш транзакции…».
- Полный хеш или ссылка на транзакцию → без предупреждения; логика поиска и сообщения поиска не меняются.
- Тесты в `src/utils/walletValidation.test.ts`; `npm run lint`, `npm test`, `npm run build` — ok; `pdk check` — 0 errors.

## Checkpoint

Полный хеш — без предупреждения, поиск как раньше. Функция getTransactionInputWarning в src/utils/walletValidation.ts, вывод в FormView.tsx (только когда у поиска нет своего сообщения).
