## Goal

Случай владельца (2026-10-04). Игроков сохраняют и по Telegram-нику (`@player`), и по названию группового чата («Alexandr + WPD Support»); у игрока бывает 2 контакта сразу, а бывает только название группы; группу помечают основным каналом. Названия групп не уникальны (есть дубли). Автосохранение игрока из T-0015 должно находить правильного игрока и не склеивать разных.

Данные рабочей БД (2026-10-04, только чтение): 129 игроков, 74 с двумя и более контактами; 14 игроков с названием группы (WPD/Support/«+»), из них у 10 есть и контакт с `@`, у 4 только группа; у 12 из 14 основной контакт — группа. Совпадений «имя» и «@имя» у разных игроков сейчас нет, одинаковых названий у разных игроков нет, но новое правило не должно это ломать.

**Вопрос L4: считать ли `alexandr` и `@alexandr` одним контактом?** В коде T-0015 (`playerContactLookupKey`, `electron/database.ts`) — считает: `@` отбрасывается, регистр не важен. Это опасно: `Alexandr` может быть названием группы одного игрока, а `@alexandr` — ником другого. Существующее сохранение игрока (`savePlayer`) их различает, поэтому автосохранение расходится с ним.

## Предлагаемое решение (на согласование)

1. Тип контакта по виду значения: ник (`@…`), телефон, email, название группы (пробелы, « + », WPD/Support) или «голое» имя без `@`.
2. **Автоматически** — только точное совпадение (NFKC, регистр, пробелы) с одним игроком по контакту, который сам по себе уникален: ник с `@`, телефон по цифрам, email. `alexandr` ≠ `@alexandr`.
3. **Только с подтверждением оператора** — всё неоднозначное: точное совпадение названия группы (названия не уникальны), совпадение без учёта `@`, название группы, содержащее ник («Alexandr + WPD Support» ↔ `@alexandr`), несколько подходящих игроков. Показывать список кандидатов (контакты, аккаунты, основной канал) и варианты «этот игрок» / «создать нового» / «не сохранять».
4. Если оператор выбрал игрока, введённый контакт можно добавить ему как дополнительный (по явной галочке); `is_primary` автосохранение не меняет никогда.
5. Пока подтверждения нет в интерфейсе — неоднозначный случай не сохраняется, под шаблоном сообщение «Найден похожий игрок, сохраните вручную».
