## Goal

Запрос владельца (2026-10-05, скриншот «Методы и лимиты»). Список методов рума трудно читать: на каждую монету+сеть отдельные строки «Депозит» и «Вывод», порядок не постоянный, есть дубли («Депозит · BTC BTC» дважды). Нужно: одна строка на монету+сеть с отметками депозит/вывод, постоянная сортировка, галочки вместо выпадающего списка операции, поля «Комментарий» и «Лимиты» — по галочке, комментарий сразу на всех языках, единые подписи при копировании кошельков (во всех румах и языках, отдельно для одного кошелька). Одно правило — в одном месте.

Факты (код и рабочая БД, 2026-10-05, только чтение):
- «через нас, p2p» под строками — это поле **Комиссия** метода (`fee_text`), не комментарий. В копируемый текст кошелька оно попадает в скобках и переводится по словарю из 3 фраз + «N% комиссия» (`src/utils/roomWalletFormatting.ts`). Остальной текст не переводится.
- «Актуальный кошелек для депозита в рум.», «Все транзакции в руме только через нас.» — сохранённые в БД значения поля **Комментарий** метода (`note`); в коде их нет. Это поле нигде, кроме редактора, не показывается.
- **Комментарий к кошельку** (`room_wallets.note`) пуст у всех 15 кошельков и тоже нигде не показывается.
- **Лимиты** (`limits_text`) используются: форма депозита/вывода предупреждает, если сумма меньше минимума. Заполнены у 11 методов (Champion вывод, test-room).
- Дубли: «BTC» и «BTC BTC» у Champion (депозит и вывод) и Nexa (депозит) — наследие старой одноразовой миграции кошельков в методы.
- Заголовок копирования всех кошельков — `roomWalletListTitle`: RU «Nexa — депозитные кошельки» (длинное тире), EN «Nexa - deposit wallets», ES «Nexa - billeteras de depósito» (дефис). У одного кошелька заголовка нет вовсе.
- В БД депозит и вывод — разные строки `room_payment_methods` с разными комиссией и лимитами (Champion: депозит Skrill без комиссии, вывод Skrill 1%).

## Предложение (на согласование)

1. **Список:** одна строка на монету+сеть, справа значки «Депозит» / «Вывод». Сортировка постоянная: монета (USDT, USDC, BTC, ETH, затем остальное по алфавиту), затем сеть (TRC20, ERC20, BEP20, …). Перетаскивание порядка убрать или оставить только внутри группы — решение владельца.
2. **Редактор:** монета, сеть, галочки «Депозит» и «Вывод». Схема БД не меняется: галочка создаёт строку метода для операции, снятие — удаляет её (с подтверждением, если у неё есть комиссия/лимиты). Комиссия и лимиты — на операцию (у депозита и вывода они разные). Блок кошелька показывается при отмеченном «Депозит».
3. **Комментарий и лимиты по галочке:** «Добавить лимиты», «Добавить комментарий» — поле появляется при отметке; пустые не хранятся.
4. **Два комментария:** оставить один. Комментарий к кошельку (пуст везде, нигде не показывается) убрать из редактора; «Комментарий» метода подписать «Заметка для оператора (игроку не копируется)». Если комментарий должен уходить игроку — это отдельное решение.
5. **Перевод:** встроенный ИИ вне scope проекта (project.md), автоматически переводить свободный текст приложение не может. Варианты: (а) выбор из списка стандартных фраз с готовыми RU/EN/ES (как сейчас «без комиссии», «через нас, p2p») + добавление новой фразы с тремя переводами; (б) три поля RU/EN/ES при включённой галочке; (в) внешний сервис перевода — нарушает ограничение, только с решением владельца.
6. **Подписи при копировании** — одна функция для всех румов и языков, одинаковое тире: «Nexa — депозитные кошельки» / «Nexa — кошелёк для депозита»; EN «Nexa — deposit wallets» / «Nexa — deposit wallet»; ES «Nexa — billeteras de depósito» / «Nexa — billetera de depósito». Копирование одного кошелька получает заголовок.
7. Дубли «BTC»/«BTC BTC» — показать в списке как одну строку; объединить в БД только с подтверждением владельца (одноразовый шаг миграции со snapshot).

## Решения владельца (2026-10-05)

- Перевод — вариант (а): комментарий выбирается из списка готовых фраз с RU/EN/ES; новая фраза добавляется один раз сразу с тремя переводами.
- Комментарий — для игрока (пример: Luxon Pay «2% комиссия»), оператору комментарий не нужен. То есть остаётся одно поле, которое уходит игроку при копировании кошелька/метода — по смыслу это нынешнее поле «Комиссия» (`fee_text`, уже показывается в скобках и переводится по словарю фраз). «Комментарий» метода (`note`) и «Комментарий к кошельку» (`room_wallets.note`) из редактора убрать.
- Перетаскивание порядка — оставить.
- Сохранённые заметки методов (`room_payment_methods.note`, Nexa: «Все транзакции в руме только через нас.» ×8, «Актуальный кошелек для депозита в рум.» ×3) — убрать (очистить одноразовым шагом миграции со snapshot); кошельки не трогать. Текст этой информации переносится в T-0020 (записан там).
- Дубли «BTC BTC» (id 1010, 362 Champion; 1050 Nexa) — удалить в БД одноразовым шагом миграции со snapshot (владелец 2026-10-05). Главное требование владельца: адреса кошельков не перепутаны и сохранены. Кошельки хранятся отдельно (`room_wallets`, ADR-0003: рум + тип сделки + монета + сеть) и с методами не связаны по id, поэтому удаление строк методов их не затрагивает; шаг миграции и снятие галочек не должны трогать `room_wallets` — тест: адреса всех кошельков до и после шага совпадают побайтно.


- Владелец принял пункты 1–7 (или свои) до изменения кода — принято 2026-10-05 с решениями выше.
- Адреса кошельков (`room_wallets`) после шага миграции и любых действий с галочками совпадают с исходными — тест на копии БД владельца и в `electron/database.test.ts`.
- Подписи копирования одинаковы во всех румах; RU/EN/ES совпадают по смыслу и форме; есть вариант для одного кошелька — тесты.
- Список методов: одна строка на монету+сеть, постоянный порядок; галочки депозит/вывод создают и удаляют строки методов без потери комиссий/лимитов другой операции — тесты на БД.
- Предупреждение о минимальной сумме в форме депозита/вывода работает как раньше.
- `npm run lint`, `npm test`, `npm run build` — ok; `pdk check` — 0 errors; ручная проверка владельца; независимый pdk-review (L3).
